# Windows 安装与更新

CloudReel 0.3.22 起以 NSIS 安装版为正式发行方式，使用 `electron-updater` 的 NSIS / GitHub provider。保留原 appId、应用名以及 `%APPDATA%/CloudReel` 数据目录；从旧便携版换装一次即可沿用片库、观看记录、设置及百度登录会话，无需复制数据库。安装前请自行完全退出旧版；应用不会关闭用户正在运行的旧版。

## 使用体验

- 默认安装到当前用户目录，可选择安装路径，通常无需管理员权限。不默认创建桌面快捷方式；开始菜单保留入口。
- 正式安装版启动 15 秒后在后台检查，之后每 6 小时检查。发现更高的正式版本后自动下载。
- 设置底部“软件更新”显示当前版本、检查按钮、进度、失败重试及按需展开的更新内容。就绪时在片库显示一次轻提示，“稍后”只关闭本次提示，不清除下载。
- 用户点击“重启并更新”后才安装，普通退出不会自动安装。播放（包括暂停）、扫描、转存、文件操作及 Trakt 同步期间主进程拒绝安装；准备重启后暂停扫描与资料任务，并阻止新的操作。
- 无新版本、网络异常、旧 Release 缺少更新描述、下载损坏均在设置中原位提示，不阻塞片库及播放。
- 开发版、解压目录、SeedHub 测试版和便携版不启用自动替换程序；显示固定的 GitHub 发布页入口。

## 发布

```powershell
npm ci
npm run setup:desktop
npm run setup:mpv
# 按 README 配置项目的公开 Trakt 发行信息
npm run dist
npm run validate:updates
```

将下列三个文件一起上传到**相同版本**的 GitHub 正式 Release。推送代码本身不会发布更新；草稿、预发布和同版本重新构建不会成为新的升级。

```text
CloudReel-Setup-0.3.22-win-x64.exe
CloudReel-Setup-0.3.22-win-x64.exe.blockmap
latest.yml
```

以后发行必须递增 `package.json` 与 lockfile 版本（例如 0.3.23），使用对应的 `v0.3.23` 标签和中文 Release 正文。更新界面从 Release 展示更新内容，按普通文本处理，不渲染上游 HTML。上传前执行 `npm run validate:updates`，核对版本、大小、SHA512、差分文件及内置更新源。不要手工修改 `latest.yml` 的版本或校验值。

仍需便携版时执行 `npm run dist:portable`。便携版文件名和安装版不同，不能替代安装包上传为自动更新资源。

## 完整性与边界

更新源固定为 `DevilSi0722/CloudReel` 的公开 GitHub Releases，主进程没有接受任意 URL、账号令牌或本地程序路径的更新接口。只接受更高的三段正式版本、明确的 Windows x64 安装包文件名及 SHA512，排除便携版、Web 安装器与预发布；下载由成熟组件校验，支持差分失败后回退全量下载。原始网络错误、下载地址和更新日志不会写到调试日志。

当前构建沿用项目既有的未签名发行方式，通过 GitHub HTTPS 和 SHA512 验证下载完整性；这不等同于发布者代码签名。日后配置 Windows 代码签名证书时，应同步设置发布者名称，启用组件已有的签名核验。GitHub 网络不可达时可重试或打开官方发布页，不自动切换到未知镜像。

本次没有数据库结构迁移。安装与卸载默认保留用户数据；覆盖升级只替换应用文件。需要清理个人数据时应由用户另行操作。

## 验证

```powershell
node --test --test-concurrency=1 tests/*.test.mjs
npm run verify:updates
npm run validate:updates
```

`verify:updates` 为测试应用生成独立的 appId、产品名、安装目录与合成用户资料，在隐藏模式真实执行 NSIS 安装、损坏下载拒绝、重新下载、静默覆盖升级和自动重启，核对片库样例、观看进度、加密凭据样例及会话分区均保留，最后卸载并清除独立测试目录。不读取或关闭正式 CloudReel，不修改正式资料或网盘。

更新界面与业务阻止规则另由隐藏窗口与服务测试覆盖。真实网盘播放仍使用应用会话副本和生产媒体中继／播放器验证，不能用本地视频替代。GitHub 线上升级需要未来发布更高版本后再验证；本地安装验收不会创建正式 Release。
