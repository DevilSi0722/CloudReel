# 发现片源：自动规范命名

CloudReel 的保存弹窗默认启用“自动规范命名，便于匹配影片资料”。用户选择文件或文件夹后，可展开命名预览，再保存到自己的百度网盘。0.3.22 改进混合命名识别和整批预览。

## 保存效果

| 内容 | 示例 |
| --- | --- |
| 电影 | `星际穿越 (2014) - 2160p.mkv` |
| 剧集 | `硅谷 - S04E03 - 1080p WEB-DL.mkv` |
| 关联字幕 | `硅谷 - S04E03 - 1080p WEB-DL.chs.ass` |

开启后会在选定位置新建独立的作品文件夹，转存完成后只重命名本次副本，然后入库。扩展名保留原样；能识别的分辨率、来源格式、编码、动态范围等版本信息保留。相同目标名称会分配版本后缀，已有文件不会被覆盖。

可以关闭自动命名，继续按原有名称转存。剧集没有季数标记时，可在弹窗调整默认季数；已有明确季数的文件保持原季数，和网站作品季数冲突的文件保留原名。

## 识别与刮削

- 作品信息由后端从 SeedHub 详情读取，包括片名、原名、首播或上映年份、季数；不接受界面传入任意文件名或作品身份。
- 已配置 TMDB 时，先匹配明确、唯一的作品结果。命名采用匹配后的片名，入库沿用相同 TMDB 身份，自动获取影片与分集资料，不再依靠原始乱码文件名重新搜索。
- 没有明确 TMDB 匹配时，采用网站作品名和可确认的季集信息入库，交由既有自动刮削处理。设置中的“自动获取影片资料”仍控制后台资料获取。
- 支持 `S04E03`、`4x03`、`EP03`、`第三集`、纯数字及方括号集数等；兼容全角字符、已知中英文片名和画质后缀，例如 `01 4K`、`05-4K`、`09~4K`、`剧名03.1080p`。先排除画质和片名中的数字，再解析集数，不按列表顺序猜测集数。
- 文件名与最近的季目录交叉核对，已有明确季数优先于默认季数。冲突、超出网站集数范围、多集合并、上下分段、合集、预告与花絮保留原名，并说明具体原因；电影目录中存在多个无法归属当前作品的视频时保留原名。
- 已匹配 TMDB 时仍保留网站片名作为识别别名，避免名称替换后无法识别原来的片名加集数格式。关联字幕只跟随同目录、同原始文件名前缀的视频。
- 同集多个版本的后缀在预览阶段提前分配，字幕同步跟随对应视频；如果保存后有新的同名文件，执行时再次检查，始终不覆盖。

## 0.3.22 的问题定位与设计

只读检查保存记录发现，《嫁金钗》的一批资源中 `01 4K.mkv`、`05-4K.mp4`、`09~4K.mp4` 等 22 个文件被旧规则跳过，仅带标准标记的第 23 集成功识别。旧数字规则不支持数字开头的画质后缀，也不接受波浪号分隔。新规则明确区分 `09~4K` 与 `09~10`，前者是第九集，后者不能当作单集。

参考 [Plex 的剧集命名说明](https://support.plex.tv/articles/naming-and-organizing-your-tv-show-files/) 与 [Jellyfin 的剧集规范](https://jellyfin.org/docs/general/server/media/shows/)，保持 `SxxEyy`、独立的版本说明及同名字幕。两者也为合并集、分段和特别篇提供独立约定；当前 CloudReel 的文件身份模型只表示单集，因此这些情况无法明确确认时保留原名，不将它们简化成第一集或顺序编号。

命名预览继续收在原保存弹窗的折叠区域。展开后每次显示 20 项，可逐步查看整批内容，移除之前服务端只返回 100 项、界面只展示 8 项的限制。有保留原名项目时才显示筛选；多目录显示原路径，方便区分重复文件名。每次加载更多只展开预览内容，不增加新的确认步骤或入口。

## 失败与恢复

保存任务分别记录转存、规范命名和入库状态。命名失败不撤销已成功保存的文件，结果会提示未完成数量；“检查状态”重用已确认的副本 ID，继续命名或入库，不重新提交转存。

目标文件身份不明、文件发生移动或变化时停止该文件的处理。任务记录只保留必要的文件身份和命名计划，不保存分享地址、提取码、Cookie、访问令牌或媒体 URL。正式片库、观看记录和手动匹配不参与本次批量重命名。
