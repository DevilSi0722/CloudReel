# 百度原文件播放 403 修复

CloudReel 0.3.20 在部分真实网盘文件上能正常列目录、获取文件信息和改名，但开始读取视频时返回 `HTTP 403 / 百度 31362`。百度错误体的可确认含义是 `sign error`，不是文件名识别失败。

## 原因与修正

原播放链路优先使用 `/api/filemetas` 返回的原文件地址。地址存在并不代表媒体端会接受它；遇到 403 后，旧逻辑刷新登录状态，再请求相同接口，仍可能获得不可用的签名。

隔离会话中的只读对比确认，同一文件的元数据地址返回 31362，其他原文件地址可以返回有效的 206 视频数据。网页签名下载接口能读取已授权测试目录中的文件，但对另外两份片库文件返回已经过期的地址：签发时间约为两小时前，有效期一小时，媒体端返回 31360。仅切换到这个接口不足以覆盖片库中的情况。

现在发生媒体访问拒绝时，会刷新登录状态并按稳定文件 ID 重新读取当前路径。视频优先通过 `VideoURL`、`nom3u8=1` 和 `dlink=1` 获取原文件地址；确认返回大小、可用的 MD5 与文件 ID，并再次查询同一 ID，核对路径和文件属性后才使用该地址。该接口不可用或没有返回地址时，继续使用网页签名下载接口。字幕等非视频文件仍使用网页下载方式。

下载地址、Cookie 和签名保留在应用自身会话与内存中，不写入片库、日志或播放器启动参数。回退地址沿用生产会话和本地媒体中继，转发 Range 请求与原始字节，保留原文件 HDR／杜比视界信息。持续拒绝时仍显示实际百度错误码；31362 现在明确提示下载签名未被接受。

## 验证

- TypeScript、前端和原生组件构建通过；完整串行回归 179 项全部通过。
- 新增回归覆盖 31362 后切换取地址方式、可用地址复用、超过 4 GB 的 Range、原文件字节、路径恢复及观看身份保留。
- 核对返回内容大小、MD5、文件 ID、处理期间的路径变化和异常下载域名；身份不一致时停止，避免读取错误文件。
- 最终 0.3.20 正式包的真实隔离会话复用 `/CloudReel-SeedHub-Test` 已保存文件，通过规范命名、身份入库、生产中继与包内 mpv 完成解码和 30 秒跳转，最终恢复原名，没有再次转存。
- 最终正式包内的真实片库 SDR 与杜比视界片源通过生产播放器解码、缓存和跳转；使用故意失效的本地路径验证按 ID 恢复，全程无需重新扫描。
- 不写入正式片库、观看进度或 Trakt，不显示或聚焦测试窗口；验证结束后删除临时会话。
